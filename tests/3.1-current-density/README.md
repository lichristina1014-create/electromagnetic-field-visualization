## 页面在讲什么

用户给的原话需求：

> 电流分体电流、面电流、线电流；面电流、线电流穿过横截线，线电流穿过点；
> 电流密度的定义就是单位时间垂直穿过单位面积 / 单位长度 / 点的电荷量。

落地成三个页签，**定义口径一字不改地通用**：

| 页签 | 电荷分布 | "穿过"的东西 | 密度 | 单位 |
|---|---|---|---|---|
| ① 体电流 | 充满一块体积 | 横截面（面积 S） | J = ρ·u | A/m² |
| ② 面电流 | 分布在一个面上 | 横截线（长度 l） | K = σ·u | A/m |
| ③ 线电流 | 分布在一条线上 | 一个点 | I = τ·u | A |

### 单位制是刻意选的（本页的核心设计）

长度 m；ρ µC/m³、σ µC/m²、τ µC/m；漂移速度 u mm/s：

```
J = ρ·u  ⇒  (ρ·1e-6 C/m³)(u·1e-3 m/s) = ρu·1e-9 A/m² = ρu nA/m²
K = σ·u  ⇒  同理                      = σu nA/m
I = τ·u  ⇒  同理                      = τu nA
```

⇒ 画面上三个读数**数值上就是 ρ·u / σ·u / τ·u**，一眼看出"同一个式子、三种量纲"。
1e-9 的因子被 nA 整个吸收，不是近似，是单位换算。

### 为什么用"载流子"讲定义

把"单位时间垂直穿过的电荷量"落到**数得着的载流子**上：每个载流子的电荷 =
该分布下总电荷 / 个数，于是

```
"单位时间穿过的载流子数 × 每个载流子的电荷" 与解析式严格相等
```

自检 `chk31.js` ② 逐例对这件事做断言（①整截面 / ①面元 / ②整线 / ②线元 / ③整点）。

## 本轮（2026-10-19）自检修掉的四个真 bug

1. **`state.show` 缺 `sec/arc/wire` 三个键** —— 写成了 `{vol,car,elem,slab,nrm,box,line,dot,ladder}`，
   ⇒ 横截面、横截线、导线**一层都画不出来**，而页面不报任何错。
   ⇒ `chk31.js` ⑥ 把"每个显示项在 `state.show` 里都有布尔值、且没有死键"钉死。
2. **`unitSegment()` 的 base 缺 `x/y`** —— `carrierPos()` 里 `base.x*b` 得到 `undefined*0 = NaN`
   ⇒ 载流子全飞、`prims` 深度全是 NaN，而 `prims.sort` 对 NaN **静默失效**
   （退化成插入序，截图看着完全正常）。⇒ `chk31.js` ⑦ 断言位置有限 + 径向不越界。
3. **讲解卡里的 `**加粗**`** —— `richHTML()` 只认 `@{...}` 与 `_x`，不认 Markdown 星号
   ⇒ 字面星号直接显示给学生。⇒ `chk31.js` ⑧⑨ 扫 DOM 与画布两侧。
4. **三个标签互相压**（`dS`×`a` 49%、`横截面 S`×`θ` 92%、`横截面 S`×`n̂` 48%）
   ⇒ `vis31.js` 用 `richLayout` 的真实宽度算包围盒，4 组相机角 × θ∈{0,40,80} 逐画面断言。

## 已知取舍

- **`dS` 的量程写死 `[0.004, 0.012]`**，不随半径 `a` 动态改滑块上限：
  推导"面元整块落在圆盘内"得 `dS ≤ 0.566a²`，而 `0.566·0.16² = 0.0145 > 0.012`
  ⇒ 整个量程内永远装得进。动态改 `max` 正是"滑块显示 ≠ 真实状态"那类静默 bug 的温床。
- **③ 页的 `S`/`l` 沿用 ①② 的 `a`/`b`**（不随页签重置）—— 面板里明确写了这句话，
  目的是让"同一个电流三种口径"读起来真的是同一根导体。
- **载流子动画按真实速度 30 倍播放**（`DRIFT_SPEED`），读数一律按滑块上的真实 `u` 算；
  面板里也写了这句，避免学生以为读数跟着动画快慢变。

## 2026-10-20 增量：面元可拖动 + 圆柱放倒（对照 PPT 第 5 页体电流图）

- **面元任意拖动**：`state.elemFX/elemFY` 是面元在横截面内的**比例坐标**（×半径 a），
  默认 (0.55, 0) 与旧版 `elemCenter=0.55a` 完全一致 ⇒ 旧断言全不破。
  指针落在面元中心 30px 内时 pointerdown 进入 `drag.mode='elem'`，屏幕位移经
  `Δp·camU=Δsx/cs、Δp·camV=−Δsy/cs`（pr 的逆映射）折算回盘内坐标；
  `elemClampFrac()` 按「角点最大半径 ≤ a」钳制（g(k) 单调 ⇒ 倍增回退必收敛）。
  盘内坐标与放倒无关（layT 只是最后一步旋转）⇒ 拖放的钳制逻辑两种姿态通用。
- **放倒**：`state.lay` + `layT(p)=(z,y,−x)`（绕 y +90°，+z→+x），内部 mode 守卫
  ⇒ 只转 ① 的场景几何，②③ 与坐标轴不动。面板「姿态」组：⤵ 放倒（相机 −1.35/0.18，
  **+x 几乎正对屏幕右方** —— az=−0.45 那版 +x 大半指向纵深，圆柱缩成一团，被否掉）、
  ⊡ 正看切面（az=el=0）。cylShell 的伪光照用**变换后**的法矢（光影跟着圆柱倒）。
- **放倒模式的标签布局**：四个标签分占四角（n̂ 贴箭尖 / dS 左下右对齐 / θ 左上右对齐 /
  半径 a 占右上）——世界方向的锚点在放倒后的某些相机下会投影到同一片屏幕区域
  （vis31 放倒断言实测 n̂×dS 57%、n̂×θ 67%）⇒ θ/dS 用**固定屏幕偏移**，与相机无关。
- **n̂ 正对镜头退化**：放倒+正看切面时 n̂ 箭头投影缩成一点 ⇒ 按制图惯例画 ⊙
  （白底橙圈+心点 = 箭头朝读者），箭长 <10px 时切换。
- **chk31 ⑱ 新增**：layT 恒等/旋转正确、放倒后面元在 x=0 盘、载流子绕 x 轴不越界、
  放倒幂等、elemClampFrac 收敛、**真实 PointerEvent 拖面元**（坐标变+不越盘+不转相机）、
  空白处拖仍是转相机、放倒拖动仍在盘内坐标系。
- **vis31 修复一个旧缺陷**：`grab()` 改了相机却没调 `setupCamera()` ⇒ `pr()` 用的是
  **上一轮**的旧相机（错位一轮）；补上后主断言与放倒断言都忠于目标视角。
