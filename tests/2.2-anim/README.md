## 场线只画「正对镜头的一圈」（2026-09-28）

原写法 `FL_PH = [0, π/2, π, 3π/2]` = **2 个互相垂直的平面**，两族线互相穿插 ⇒ 用户嫌乱。
现在由 `facePH()` / `faceCurves()`（`new_a.js`）统一给出**一个平面**的 2 个方位角：

```js
const facePH = ()=>{ const ph=cam.az+Math.PI/2; return [ph, ph+Math.PI]; };
```

- 为什么是 `az + π/2`（**差 90° 正好是最乱的那个结果**）：
  子午面 φ 的径向方向 `u = (cosφ, sinφ, 0)`；`φ = az+π/2` ⟹ `u ≡ camU`（屏幕水平轴）
  ⟹ 横向零缩短、屏幕**左右严格镜像**。若误写成 `φ = az` 则 `u ⊥ camU` ⟹ 平面侧对镜头、
  整族线被压成一条线（就是用户截图里最乱的样子）。
- **不是** `n ∥ camD`：`n` 的 z 分量恒为 0、`camD` 的 z 分量是 `sin(el)`，永远不可能平行；
  此时 `n` 与视线夹 `el` 角 = 相机仰角（不可避免，也不影响可读性）。
- 平面无向：`φ` 与 `φ+π` 是同一个平面，而 `dipolarLines()` / `equiCurve()` 只给 `x ≥ 0` 的半条
  ⟹ **必须两个方位都转**才拼得出完整的一圈。但**轴上的段（x ≡ 0）**转两次是同一批点 ⟹ 去重。
- 三个调用点：`new_a.js` `drawFieldLines`、`new_b.js` `drawEqui`、`new_b.js` `sceneShield`
  （含腔内径向箭头 `phs`，20 → 10 支）。`drawFlow` 的迁移弧**没动** —— 它有自己的一套调参
  （`az+0.55`，故意"半开着"），改成 +π/2 会完全张开、和场线糊在一起。

## 电荷符号加大加粗（2026-09-28）

用户原话：*"正电荷的加号希望再大一些再粗一些 不然看不清"*。

**★ 根因不是"字号给小了"，而是 PingFang 的 `+` 字形远小于字号、且笔画极细。**
把字形真画到离屏画布上量像素（`cdpeval` + `getImageData`）：

| 字号 | 字形 bbox | 臂厚 |
|---|---|---|
| 9（改前最小档） | **4×4 px** | 1~2 px |
| 15（改前最大档，两极） | **8×8 px** | 2 px |
| 27 | 14×14 px | **仍只有 2 px** |
| 36 | 18×19 px | 4 px |

⇒ 结论：**纯靠加字号解决不了"细"**（要 36px 才有 4px 臂厚），而且 mag 小的那些符号会跟着
一起变巨大、把"两极最密、赤道为零"的**密度梯度**抹平（那是 σ = 3ε₀E₀cosθ 的教学载荷）。

修法两条（`new_a.js`）：

```js
const CHG_SZ  = mag => 11 + 19*mag;      /* 字号 11..30 ⇒ 字形约 9..16 px */
const CHG_FAT = mag => 0.9 + 0.6*mag;    /* 同色描边宽度 ⇒ 臂厚 3..4 px */
```

- **`fat` = 共享引擎里的同色描边**（`2.1` 的 `richDraw(ctx,lo,cx,cy,align,color,fat)` 第 7 个参数，
  `text(p,str,{fat:…})` 透传）。它画在白描边光环**之后**、`fillText` **之前** ⇒ 不会被光环啃掉。
  默认 `0` ⇒ 其余页面（1.2~1.5 / index / 2.5）**零影响**（已用截图 sha256 逐字节验证）。
- ⚠️ `fat` 与字号**解耦**，所以大符号粗、小符号也粗；梯度仍由 `size` + `alpha` 承担。
- ⚠️⚠️ `SEPS`（屏幕最小间距）**必须跟着字号一起抬**：15 → 25。实测旧组合下最小间距
  **恰好**被压到 15.1 px，说明这个过滤器本来就"顶格"在工作、一点余量都没有。
  定 25 而不是 21 的第二个理由见下条。
- ⚠️ 判"两个符号会不会互相压住"要看 `ctx.measureText` 的**前进宽**（= 白描边光环的横向占地，
  `t1d` 的包围盒重叠判据就是这么算的），不是**墨迹宽**。PingFang 的 U+2212 前进宽 ≈ 0.77 em
  ⇒ 字号 30 时 23.1 px；`SEPS=21` 时 `t1d` 在 `(−478,519)×(−501,518)` 抓到 0.2 px 的盒相交
  （墨迹其实还差 4 px，但那 0.2 px 说明"再挤一点就真的糊了"）。
- `avoidRect` 的余量 ±6 → ±10（字形变大后，中心刚好在阶段卡外 7px 的符号会压到卡片边）。
